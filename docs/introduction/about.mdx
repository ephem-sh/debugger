# About debugger

debugger is a dev-only observability layer that captures browser and
server-side logs, errors, network requests, and application state from
your running dev server. AI agents query this data through the `dbg`
CLI to understand what's happening in your app without needing browser
access.

## How it works

debugger has three parts:

1. **Server instrumentation** — patches `console.*` methods and starts
   an IPC bridge when your dev server boots. Captures server-side logs
   and errors.
2. **Browser client** — a lightweight IIFE script injected into your
   page during development. Captures console output, runtime errors,
   network requests (fetch, XHR, WebSocket), and application state
   (cookies, storage, service workers, permissions, quota).
3. **CLI (`dbg`)** — queries the running session over IPC. Returns
   structured, filterable output that agents and developers can read.

## Architecture

```
Browser --> same-origin POST /_/d --> Next.js server --> LogStore (ring buffers)
                                                              |
Server console/errors ----------------------------------------+
                                                              |
CLI (dbg) --> IPC socket/pipe --> LogStore --> formatted output
```

All data lives in memory using fixed-capacity ring buffers. Nothing
is written to disk. The socket directory (`.debugger/` on Unix,
named pipes on Windows) is the only filesystem artifact.

## Key principles

- **Dev-only.** Zero runtime cost in production. The instrumentation
  no-ops when `NODE_ENV` isn't `development`.
- **Zero dependencies.** The core package has no external dependencies.
- **No configuration.** Install, wire up two lines, and it works.
- **Agent-first.** The CLI outputs structured data (`--json`) that
  AI agents consume directly. Human-readable formatting is the default.
- **Privacy-aware.** Same-origin data collection avoids ad-blocker
  interference. No data leaves your machine.

## Browser detection

debugger identifies which browser sent each entry. Detection covers
40+ browsers including Chrome, Firefox, Safari, Edge, Brave, Arc, Dia,
Vivaldi, Opera, and more. Unknown browsers are identified by parsing
the User-Agent string automatically.

## What debugger captures

| Scope | Data | Source |
|-------|------|--------|
| Console | `log`, `warn`, `error`, `debug`, `info` | Browser + Server |
| Errors | Uncaught errors, unhandled rejections, SSR errors | Browser + Server |
| Network | Fetch, XHR, WebSocket (URL, status, timing, headers) | Browser |
| Cookies | Name, value, flags (Secure, SameSite, expiry) | Browser |
| Storage | localStorage + sessionStorage snapshots | Browser |
| Workers | Service worker registrations | Browser |
| Cache | Cache Storage names and entry counts | Browser |
| Permissions | Geolocation, camera, notifications, etc. | Browser |
| Quota | Storage usage and quota estimates | Browser |
